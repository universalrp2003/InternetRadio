# mls-rs / AWS-LC feasibility lane (TEST ONLY)

This separate harness evaluates the published **mls-rs 0.56.0** MLS implementation with the project's **AWS-LC provider 0.25.0**, restricted to `CipherSuite::CURVE25519_AES128` (the RFC 9420 X25519 / AES-128-GCM / SHA-256 / Ed25519 suite). Hosted run [38679021757](https://github.com/universalrp2003/InternetRadio/actions/runs/38679021757) passed the initial in-memory fixture, Clippy, JNI host check, Android dependency inspection, license-metadata inventory, RustSec, four-ABI APK build, and API 35 emulator smoke. Follow-up [38681945215](https://github.com/universalrp2003/InternetRadio/actions/runs/38681945215) added and passed the host-only SQLCipher persistence/restart fixture. Latest run [38688708114](https://github.com/universalrp2003/InternetRadio/actions/runs/38688708114) passed formatting, the two-member fixture (ciphertext tamper rejection, fresh next-generation recovery, replay rejection, and a forged same-label KeyPackage with an unpinned signing key), the host SQLCipher persistence/restart test, Clippy, JNI host check, standard and optional dependency-graph checks, license-metadata inventory, RustSec, optional vendored-OpenSSL SQLCipher cross-build for all four Android ABIs, standard four-ABI APK build, and API 35 emulator smoke. The standard APK excludes SQLCipher/OpenSSL; the separate SQLCipher build is compile-only. Cargo inventory checks declared license expressions or license-file paths; it is not legal compatibility approval or a complete notice review. GitHub marks the 386887 RustSec and license-inventory steps successful and its check annotations contain no RustSec finding warning, but the raw logs and `secretmessage-mls-rs-candidate-review` artifact could not be downloaded from this workspace because the Actions result-storage host is inaccessible here. Exact per-crate RustSec diagnostics and package-level license declarations remain unreviewed; do not infer security clearance, zero advisories, or legal compatibility from step status alone. Earlier run [38664410994](https://github.com/universalrp2003/InternetRadio/actions/runs/38664410994) also passed and reported no RustSec findings in its generated candidate lockfile. An initial negative-test attempt in [38669823568](https://github.com/universalrp2003/InternetRadio/actions/runs/38669823568) incorrectly retried the exact same message generation after a failed tamper and got `KeyMissing(0)`; the fixture now tests a fresh next-generation message instead. This is an observed test-path behavior, not a security finding or a general delivery/retry guarantee. The standalone test APK now exposes test-only native host/join methods that exchange a fixed MLS KeyPackage/Welcome and synthetic application-message markers over a direct private-LAN TCP connection. Only fixed synthetic bytes are sent; no user text or chat history is supported. The LAN identity provider is mls-rs `BasicIdentityProvider`, which accepts any BasicCredential and is not a real identity trust policy. Since test APK 0.3.0, both phones first show a 20-digit safety code from the group's RFC 9420 epoch authenticator; the fixed messages are exchanged only after both testers confirm the same code, and a mismatch report on either phone stops both. Since 0.4.0, the bridge also creates a persistent per-install Ed25519 test identity for the app to keep Keystore-wrapped, uses the device ID from the BasicCredential label to classify the other phone as new, remembered or changed against the app's remembered keys, and reports the verified peer after a PASS. Run [38884976838](https://github.com/universalrp2003/InternetRadio/actions/runs/38884976838) passed every step of this lane with these changes. Run [38850979289](https://github.com/universalrp2003/InternetRadio/actions/runs/38850979289) passed every step of this lane with the safety-code comparison and its host tests. The offline product preview stays isolated from this harness. Since 17 October 2026 the separate, owner-approved Secret Message Wi-Fi TEST build (`secretmessage/wifi-test`) links it through its own JNI exports and the `WIFI_CHAT` profile (protocol `secretmessage-wifi-chat/1`, encoded messages of up to 96 KiB, 60-minute chats), and a waiting host can be stopped; the smoke test APK keeps `secretmessage-lan-test/6`. Run [39030176452](https://github.com/universalrp2003/InternetRadio/actions/runs/39030176452) passed every gated step with these changes. For that build's Internet path (0.4.0-internet-test), the session code now runs over any stream with timeouts and a write shutdown, a TCP socket or one end of a Unix socket pair: `open_relay_pipe` creates the pair in safe Rust and hands the app its end as a file descriptor (`IntoRawFd`, no unsafe code), and `run_relay_mls_host`/`run_relay_mls_join` run the unchanged session over the other end while the app copies bytes to and from the owner's test relay (`secretmessage/relay`). Host tests run a complete Wi-Fi-profile chat through a stand-in relay that splits the bytes into uneven pieces, check that a lost relay connection stops both phones, and check that a relay pipe is prepared for one chat only.

The upstream project is actively maintained and publishes Apache-2.0-or-MIT licensed crates. Its README explicitly says it has not received a full third-party security audit. Its provider table marks AWS-LC as stable and RustCrypto as experimental; this lane uses AWS-LC and does not enable experimental post-quantum suites. The manifest enables AWS-LC's upstream `bindgen` feature for Android cross-compilation; no cryptographic code is patched. Those upstream statements are not an audit of the resolved dependency graph or an endorsement for this product.

The in-memory fixture runs two synthetic members in one process and tests bidirectional MLS application-message round trips, absence of fixed plaintext markers in serialized messages, tamper rejection, fresh next-generation recovery, replay rejection, and rejection of a same-label forged KeyPackage using an exact synthetic `SigningIdentity` allowlist. The separate LAN fixture now creates independent host and guest MLS clients, transfers a KeyPackage and Welcome, asks both people to compare the epoch-authenticator safety code and exchanges their answers as MLS application messages, then exchanges three fixed MLS application-message markers over a framed TCP stream. Since test APK 0.5.0 the same session then carries short typed test messages as MLS application messages, with encrypted delivery acknowledgments and an end marker; the text is shown on screen only and never stored, and host tests cover both directions, malformed payloads, a dropped connection and a peer running another protocol version. Host tests also cover the code format, a mismatch report on either side, and different codes for a relaying device's two separate groups; the host-loopback test passed in [run 38708505612](https://github.com/universalrp2003/InternetRadio/actions/runs/38708505612), as did the four-ABI test APK build. The hosted API 35 emulator smoke passed there too, but exercises only the local in-memory path. The Android app offers an expiring one-peer invite URI, shares it through the Android share sheet, and restricts the test client to a private IPv4 address. The test LAN provider uses upstream `BasicIdentityProvider` and therefore accepts any BasicCredential: it does not authenticate a person or device, and the SMS invite is not identity verification. The first user-reported physical-device run of this LAN path passed on 2026-10-15: OPPO CPH1803 (Android 8.1/API 27, arm64-v8a; local in-memory and LAN PASS) and Xiaomi 2406ERN9CI (Android 16/API 36, arm64-v8a; LAN PASS, local smoke not run). Both reported a direct same-Wi-Fi exchange of fixed synthetic MLS messages only, with no user text or chat history sent or stored. This is a narrow test-only result, not product integration, real identity authentication, internet P2P/TURN, persistence, or security approval. The smoke bridge is a minimal test-only JNI wrapper; it does not validate the upstream UniFFI wrapper, which is coupled to the OpenSSL provider in this release. No message persistence, Android Keystore, internet P2P, TURN, production identity, or security approval is provided.

The optional `storage-spike` Cargo feature is a separate test-only SQLCipher experiment. Its persistence/restart test runs on the host: it explicitly calls the upstream `Group::write_to_storage()` after the commit and after sending, stores the MLS group state through the SQLCipher provider, closes and reconstructs the client, reloads the group, and proves a fresh message still decrypts on the other fixture member. mls-rs documents that group changes are not persisted automatically until this explicit call; a product must prove it checkpoints every relevant state/ratchet mutation without creating message-history persistence. The host test also checks that a fixed test-only plaintext marker is absent from the database bytes and that an incorrect database key cannot reopen the state. The first four-ABI Android SQLCipher cross-build [38683217102](https://github.com/universalrp2003/InternetRadio/actions/runs/38683217102) failed because bundled SQLCipher required `openssl/crypto.h`, absent from the Android NDK. The next attempt [38684689429](https://github.com/universalrp2003/InternetRadio/actions/runs/38684689429) enabled rusqlite's `bundled-sqlcipher-vendored-openssl` feature but failed when OpenSSL's install step could not find `aarch64-linux-android-ranlib`. A further run [38687345624](https://github.com/universalrp2003/InternetRadio/actions/runs/38687345624) built the aarch64 SQLCipher variant but then failed on Armv7 because OpenSSL expected `arm-linux-androideabi-ranlib`; reusing the same Cargo target directory also caused the following baseline AWS-LC build to fail in CMake. The follow-up [38688708114](https://github.com/universalrp2003/InternetRadio/actions/runs/38688708114) passed the optional SQLCipher/vendored-OpenSSL cross-build for all four Android ABIs after adding the target-prefix aliases and isolating the Cargo target cache. This introduces a separate OpenSSL crypto library alongside AWS-LC and requires a full dependency/license/RustSec/security review; it is test-only and not product-selected. The passing cross-build proves compilation only, not Android SQLCipher runtime behavior or Keystore integration. The standard `android-jni` feature and APK remain without SQLCipher/OpenSSL. The isolated feature does not persist or protect the signing identity, exercise Android Keystore wrapping, verify flash-level erasure, backup/migration or power-loss recovery, or establish that this storage design is fit for the product. The fixed database key exists only in the host test fixture.

The CI lane records the generated lockfile, runs both host fixtures, Clippy/RustSec and a Cargo license-metadata inventory, inspects the standard Android, host storage, and optional Android SQLCipher graphs separately, cross-builds the SQLCipher feature for four Android ABIs, builds the standard APK for four Android ABIs, and launches that baseline fixture on a hosted API 35 emulator. Run 38688708114 passed these checks. Passing feasibility checks do not grant security or release approval. Keep all RustSec findings visible; do not ignore advisories or use this candidate for sensitive communications. No product integration or publication is authorized by this test lane.
