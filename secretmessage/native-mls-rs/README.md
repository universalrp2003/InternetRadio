# mls-rs / AWS-LC feasibility lane (TEST ONLY)

This separate harness evaluates the published **mls-rs 0.56.0** MLS implementation with the project's **AWS-LC provider 0.25.0**, restricted to `CipherSuite::CURVE25519_AES128` (the RFC 9420 X25519 / AES-128-GCM / SHA-256 / Ed25519 suite). Hosted run [38679021757](https://github.com/universalrp2003/InternetRadio/actions/runs/38679021757) passed the original in-memory fixture, Clippy, JNI host check, Android dependency inspection, license-metadata inventory, RustSec, four-ABI APK build, and API 35 emulator smoke. Follow-up run [38681945215](https://github.com/universalrp2003/InternetRadio/actions/runs/38681945215) passed formatting, the two-member fixture (including ciphertext tamper rejection, fresh next-generation recovery, replay rejection, and rejection of a same-label KeyPackage with an unpinned signing key), the host-only SQLCipher persistence/restart test, Clippy, JNI host check, standard Android JNI and host SQLCipher storage dependency-graph checks, license-metadata inventory, RustSec, four-ABI APK build, and API 35 emulator smoke. The latest license inventory checks declared Cargo license expressions or license-file paths across the Android and optional storage-spike candidate graphs; it is not legal compatibility approval or a complete notice review. A later run [38683217102](https://github.com/universalrp2003/InternetRadio/actions/runs/38683217102) passed the host fixtures, standard Android dependency graph, license/RustSec steps and baseline APK/emulator checks, but its optional SQLCipher Android cross-build failed because the NDK lacks the OpenSSL headers used by SQLCipher. GitHub marks the 386819 audit/inventory steps successful and its check annotations show no RustSec finding warning, but the raw audit log and `secretmessage-mls-rs-candidate-review` artifacts could not be downloaded from this workspace because the Actions result-storage host is inaccessible here. Therefore the exact per-crate RustSec diagnostics and license declarations remain unreviewed; do not infer security clearance, zero advisories, or legal compatibility from step status alone. Earlier run [38664410994](https://github.com/universalrp2003/InternetRadio/actions/runs/38664410994) also passed and reported no RustSec findings in its generated candidate lockfile. An initial negative-test attempt in [38669823568](https://github.com/universalrp2003/InternetRadio/actions/runs/38669823568) incorrectly retried the exact same message generation after a failed tamper and got `KeyMissing(0)`; the fixture now tests a fresh next-generation message instead. This is an observed test-path behavior, not a security finding or a general delivery/retry guarantee. It reuses only the existing small JNI entry point and standalone smoke APK; the protocol implementation and crypto provider come from upstream crates. The candidate is not linked into the Secret Message product application.

The upstream project is actively maintained and publishes Apache-2.0-or-MIT licensed crates. Its README explicitly says it has not received a full third-party security audit. Its provider table marks AWS-LC as stable and RustCrypto as experimental; this lane uses AWS-LC and does not enable experimental post-quantum suites. The manifest enables AWS-LC's upstream `bindgen` feature for Android cross-compilation; no cryptographic code is patched. Those upstream statements are not an audit of the resolved dependency graph or an endorsement for this product.

The harness runs a synthetic two-member, in-memory group and serializes MLS messages at the simulated transport boundary. It checks bidirectional application-message round trips, absence of test plaintext in the wire bytes, rejection of a modified ciphertext in both directions, acceptance of a fresh next-generation message after each rejected ciphertext, and rejection of replayed messages after successful delivery. It deliberately does not assume that retrying the exact same MLS ciphertext after a failed decryption will succeed. The fixture also uses a test-only exact-`SigningIdentity` allowlist to reject a forged KeyPackage that reuses Bob's `BasicCredential` label with a different signing key. The labels and pinset are synthetic; this does not implement QR/safety-code exchange, real-device identity, or a production trust system. These assertions exercise this pinned candidate's message-processing path only; they are not a general cryptographic review. The smoke bridge is a minimal test-only JNI wrapper; it does not validate the upstream UniFFI wrapper, which is coupled to the OpenSSL provider in this release. A Kotlin product integration would still need a reviewed wrapper/provider design. This test does not validate real device identity, persistent key protection, network delivery, two-phone interop, or message-expiry behavior.

The optional `storage-spike` Cargo feature is a separate test-only SQLCipher experiment. Its persistence/restart test runs on the host: it explicitly calls the upstream `Group::write_to_storage()` after the commit and after sending, stores the MLS group state through the SQLCipher provider, closes and reconstructs the client, reloads the group, and proves a fresh message still decrypts on the other fixture member. mls-rs documents that group changes are not persisted automatically until this explicit call; a product must prove it checkpoints every relevant state/ratchet mutation without creating message-history persistence. The host test also checks that a fixed test-only plaintext marker is absent from the database bytes and that an incorrect database key cannot reopen the state. The first four-ABI Android SQLCipher cross-build attempt [38683217102](https://github.com/universalrp2003/InternetRadio/actions/runs/38683217102) failed because the bundled SQLCipher C source required `openssl/crypto.h`, which the Android NDK does not provide. The isolated feature now opts into rusqlite's `bundled-sqlcipher-vendored-openssl` backend; a rerun is pending. That introduces a separate OpenSSL crypto library alongside AWS-LC and requires a full dependency/license/RustSec/security review; it is test-only and not product-selected. Even if a later cross-build passes, it proves compilation only, not Android SQLCipher runtime behavior or Keystore integration. The standard `android-jni` feature and APK remain without SQLCipher/OpenSSL. The isolated feature does not persist or protect the signing identity, exercise Android Keystore wrapping, verify flash-level erasure, backup/migration or power-loss recovery, or establish that this storage design is fit for the product. The fixed database key exists only in the host test fixture.

CI will record the generated lockfile, run both the in-memory host fixture and the optional host SQLCipher persistence/restart experiment, run Clippy/RustSec and a Cargo license-metadata inventory, inspect the standard Android, host storage, and optional Android SQLCipher graphs separately, cross-build the SQLCipher feature for four Android ABIs, build the standard standalone APK for four Android ABIs, and launch that baseline fixture on a hosted API 35 emulator. Even if those feasibility checks pass, this does not grant security/release approval. Keep all RustSec findings visible; do not ignore advisories or use this candidate for sensitive communications. No product integration or publication is authorized by this test lane.
