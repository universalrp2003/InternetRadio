## What 2.41 changes (code 46)

Four owner-requested changes, and no other behaviour change:

1. **Honest watts/amps.** The charging numbers on the notification card and the battery
   card are now named for what they are — **battery-side** measurements
   (`V_batt × I_batt`, the only charging number Android exposes) — and are shown only when
   the phone actually reported them. Amps are no longer substituted where watts belong,
   current is always shown as a magnitude with its own unit, and a missing sensor stays
   "Not reported" instead of becoming `0.00 W`. Implausible kernel values (voltage outside
   2–12 V, current beyond 20 A, watts beyond 150 W, non-finite spikes) are refused rather
   than displayed. One shared policy
   (`data/ChargingHonestyPolicy.kt`) now also computes the reading used by the battery
   reader, so the card, the health screen and the pill cannot disagree.
2. **Screen-on/off charging note.** While charging, the card and the battery screen say
   plainly that the screen's own draw changes what the battery-side figure reads — and
   that the figure is measured at the battery, never the charger adapter's output. That is
   a measurement note, not a fault and not a claim about the charger.
3. **AI output-budget + provider model check.** Every generation ask carries a bounded
   output-token budget (32 minimum for a real answer, 4 000 maximum; the model list keeps
   zero). A request whose own deadline is nearly spent asks for a *shorter* answer instead
   of being handed an open-ended budget and timing out. On top of that, after "Load models"
   the app now compares the saved model with the provider's own `/models` list: a model the
   provider does not contain is rejected with the existing translatable message instead of
   producing a doomed request, and the same check runs before the connection test. An
   unavailable list is never treated as evidence against the model.
4. **44 °C heat warning.** The battery heat threshold is now **44 °C** (it was 45 °C in the
   voice path and 42 °C in one plug-in check — two numbers for one thing). A single policy
   (`data/ThermalWarningPolicy.kt`) decides the warning, names the sensor honestly (battery
   vs CPU zone), formats the temperature, and hushes a repeat for 3 hours. The app never
   claims a cause, never calls the phone damaged, and never invents a temperature when no
   sensor reported one.

Both languages cover every new string (941 audited EN/TA catalog keys, 931 before 2.41).

## What 2.41 does **not** do

- It does not re-add notification/message reading, accessibility, contacts, SMS or call-log
  access. The retired 2.39 reader stays removed and archived reference-only.
- It does not disable, bypass or weaken Play Protect, rename the package, change the signing
  identity or hide the installation source.
- It does not claim that the 44 °C figure is a diagnosis, that the charging watts are the
  charger's output, or that a model list proves a key/account/quota will work.
- It does not touch the published 2.40 assets, the 2.39 history,
  `docs/live-guard-play-protect-install-block.md`, or Ramesh Radio 1.8 / PulseEQ 1.2 bytes.

  DEX gate, the new 2.41 DEX gate for the honest-charging/heat/AI-budget symbols in **both**

  digest, so if the rebuild does not reproduce the tested bytes the workflow promotes the
  recorded run's `cleansweep-apk` artifact after verifying its digest against the evidence
  file — the gate is deliberately not weakened.

## Installation (after publication only)

Install the exact `CleanSweep-v2.41.apk` published on the release page with **Play Protect
left ON**, from the normal download route. Do not use adb or a modified build. The published
APK is the exact device-tested bytes; a different digest is a different build and is not
covered by the recorded device test.
