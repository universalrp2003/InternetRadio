# Live Guard / CleanSweep 2.35 — all six insights improvements

## New

1. **Honest, dated dashboard.** Unrun permission checks and missing ping, jitter,
   RAM or storage readings stay **Not checked / Not measured / Not reported**.
   There are no manufactured 95/100 or 35 ms defaults. A permission-review score
   is not malware detection or a safety certificate. Network work runs off the UI
   thread; unknown quality is neutral, not “good”. The small live TCP probe is
   active network traffic, not a speed test or a zero-data feature.
2. **Check Live Guard on this phone.** Home → **History & tools → Self-test**
   shows the actual model, Android/API/app version, relevant permission/configuration
   flags and sensor availability. **Preview / share safe report** exports an
   allowlisted text report only after your action. No keys, installed-app identities,
   SMS/photos/files, raw logs, prompts, IP/SSID or serial/device identifiers.
   Granted permission is not proof of OEM overlay placement or background survival.
3. **Security changes timeline.** Optional local recording tracks newly observed
   apps/access, changed evidence, explicit reviewed/expected choices and findings
   no longer observed after comparable checks. Stable package/component identities
   prevent same-name collisions. First available checks establish a baseline, not
   invented new threats. Failed/incomplete/out-of-scope reads cannot resolve old
   findings. App visibility changes are not proof of install/uninstall or malware.
4. **Local charging history and charts.** Optional observed sessions show start/end
   percentage, elapsed-time duration, sampled mean/peak battery-side watts,
   temperature, measurement coverage and observed 20% → 80% intervals. Recent
   power/temperature charts leave unknown/long-gap segments open. Two sufficiently
   observed intervals can be compared, not ranked as adapter efficiency. Missed
   starts/ends, interruptions and reboots are explicit; no charger-output claims. Reboots/long gaps create partial
   segments rather than joining incompatible uptime clocks.
5. **Data budget and daily history.** Set your actual period/recharge start and expiry/next reset date;
   calculate a remaining daily allowance and, when sufficient complete history
   exists, an estimated run-out pace. Expiry is inclusive in the phone's calendar; a next-reset day is exclusive.
   A historical start date queries Android totals from that local midnight, not the
   exact carrier recharge hour. Missing earlier fallback traffic is not reconstructed.
   Quota, recharge reset and expiry changes remain manual. Complete past-day
   Android cellular history can be viewed; saving is optional. Counter fallbacks
   are explicitly partial/reset-sensitive; unsupported precise forecasts are withheld.
   Device-wide SIM traffic is not the carrier's bill or per-SIM official balance.
   Unlimited 5G is a user-configured preference, not carrier eligibility verification.
6. **Grounded AI-linked action checklist.** **Do first / Optional review / Leave
   alone–expected** comes from local findings and your acknowledgements. Available
   heat/storage/data/network observations link to relevant local tools; security
   steps reuse the guarded exact-target settings routes. AI can supply optional,
   evidence-bound explanations, never arbitrary intents/packages/URLs, priority
   downgrades, automatic revocation/uninstall/deletion or a resolved state. Invalid
   or unavailable AI output leaves the local checklist usable. Fresh **Recheck**
   verifies observations; **Reviewed/expected** leaves access unchanged.

## User control and retention

All three passive history switches default **OFF**. Histories are bounded and
private in the app's no-backup storage: security up to **200 events**, charging up
to **30 sessions / 30 days** with **240 chart points** per session, daily mobile
history up to **90 daily records**. Each tab has a clear control. Turning recording off
pauses collection, rather than deleting existing history. Explicit review choices
are saved when you click them even if passive security history is off; clearing
security history also clears those choices. Expired charging entries are pruned on the next
local read, not by a newly enabled background cleanup job. Unreadable/corrupt history
is flagged and not silently overwritten; failed erasure is not reported as success.
There is no automatic cloud history
sync and no extra monitoring service is enabled by a history switch.

## Preserved

- Connected compact pill is **watts only**, including full/paused charging; unavailable
  power is `— W`. No data/D/U/quota decoration while connected.
- Unplug restores the normal view when background monitoring was enabled;
  charging-only mode stops without changing preferences.
- Guarded finding-specific settings, complete fresh AI reports, privacy switches,
  selected provider/fallback disclosure, English/Tamil menus and offline assistant.
- Same application ID/signing certificate; Android **8.0/API 26+** target.
  Ramesh Radio **1.8** and PulseEQ **1.2** are unchanged maintained-app companions.
  Legacy AppForge and original Internet Radio modules remain intact.

## Downloads

Install **CleanSweep-v2.35.apk**; the launcher name is **Live Guard**. Install over
2.34 without uninstalling. APKs and AABs for all three maintained apps are attached;
AABs are not directly installable. The previous 2.34 release is not overwritten.

## Validation and limits

Publication requires debug/release compilation, both CleanSweep unit-test variants,
**113 required cases per variant** (27 previous + 86 new), existing Radio tests,
release APK/AAB generation, APK feature/manifest checks, minSDK/version checks,
non-debuggable release verification and the unchanged project signing certificate.
The report gate rejects missing/skipped/failed required suites and the APK gate
checks the new insight classes are packaged.

The initial development candidate passed [cloud validation](https://github.com/universalrp2003/InternetRadio/actions/runs/38067648280)
with 109 required cases per variant. The final source adds boot/gap, exact-threshold,
retention, plan-start/date-mode and storage-error hardening; publication re-runs
all gates with **113 required cases per variant** on the actual release source.

These automated policies/compilation checks do **not** validate physical charging,
OEM sensor calibration, every Settings activity, overlay rendering, force-stop,
reboot survival or carrier billing accuracy. No phone/emulator is available in the
coding environment. The owner's earlier Redmi 13 5G confirmation concerns **2.34
charging/unplug display only**, not the new 2.35 features or other devices; its
Android/MIUI/HyperOS version was not supplied.

See the [2.35 real-device test plan](https://github.com/universalrp2003/InternetRadio/blob/arena/5cb8f828-internetradio/docs/live-guard-2.35-device-test-plan.md)
and [privacy policy](https://github.com/universalrp2003/InternetRadio/blob/arena/5cb8f828-internetradio/PRIVACY.md).
GitHub publication is not app-store approval. AI advice can be wrong; no feature
certifies a malware-free or chemically healthy battery.
